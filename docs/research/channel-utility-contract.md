# Channel utility implementation and evidence

The original Halftrack device follows the public workflow described in the [reference manual's Utility section](https://www.ableton.com/en/live-manual/12/live-audio-effect-reference/#utility), consulted 2026-10-14. That description establishes independent input polarity switches, stereo channel selection, width and alternative mid/side control, mono and bass-mono processing, bass audition, gain, balance, mute and DC removal. Single-channel selection disables width/mid-side control. This is a behavioral specification, not recovered source, and it does not establish filter coefficients, interpolation, precise order or identical sound. No reference media, presets, implementation or visual assets are distributed.

## Original signal contract

All samples use stereo floating point with headroom. Gain ranges from a serialized -100 dB silence sentinel to +35 dB. Balance uses constant-power sine/cosine gains normalized to unity at center, reaching +3.01 dB on the retained channel at either extreme. Polarity precedes channel selection. Left/Right duplicate the chosen input; Swap exchanges inputs. Stereo width multiplies the difference signal from 0 to 4 while preserving the sum. The alternate signed mid/side setting retains both components at zero, reduces side toward zero at -1, and reduces mid toward zero at +1. Mono forces the side weight to zero. Disabled values remain serialized and undoable.

Bass processing uses a bilinear third-order Butterworth crossover at 50–500 Hz, default 120 Hz. Each high/low branch factors into a first-order real-pole section and a second-order section with Q=1. Normal bass-mono processing preserves mid and high-passes side; audition instead selects low-passed mid in both channels while bass mono is enabled. These filters retain unweighted input history, followed by mid/side weights. Output gain/balance follows, then a 5 Hz second-order DC high-pass with Q=0.5 and unity Nyquist gain, then mute. Filters continue maintaining state while disabled. Gain, balance, mid/side weights and mute use five-millisecond linear transitions after first processing; discrete switches and bass-frequency coefficient changes are not smoothed. The filter topology follows the trace described below; exact coefficients, filter realization, control timing and other defaults still need controlled reference measurements.

## Application integration

The device inserts after instrument/return input and existing insert effects, before send taps and mixer. Audio tracks, MIDI instrument tracks and returns share one processor. Add, edit, bypass, move and remove participate in engine undo. The native editor exposes every implemented parameter, groups slider drags into one undo step and follows the device's stable identity. Project XML retains all fourteen properties. Nonfinite/out-of-range values are rejected before replacing the current edit; absent properties select documented defaults.

Parameter packets cross a bounded single-producer/single-consumer queue. If full, the message-thread timer retries the latest full packet. Playback is drained before export resets that queue. Audio processing uses no owned heap allocations, locks or I/O. This does not certify the engine or arbitrary hosted plugins.

## Verification boundaries

`utility-acceptance` uses 320 independent constant-matrix cases, independent third-order bass impulse samples and frequency-response laws, closed-form two-pole DC step behavior at four rates, full-scale headroom, exact steady mute, block partition invariance, filter reset, finite-input handling, a known five-millisecond gain ramp and mono/mute transitions with existing filter history.

Generated audio and MIDI projects exercise complete-file exports, insert ordering, pre-fader return processing, bypass, removal, undo/redo, stable identity, all-property persistence, and malformed-load preservation. Production editor handlers cover gesture undo and retained disabled values; generated native-window tests cover removal, undo/reopen and project replacement. Runtime C++ allocation guards and concurrent packet checks cover the owned DSP and its queue separately.

Automated synthetic tests do not establish physical hardware performance, mouse delivery, proprietary DSP identity, long-session stability or complete device parity. Native manual checks are listed in `docs/manual-test-phase1.md` and remain unrun unless separately recorded.

## Binary-assisted filter refinement

The isolated ARM64 12.2.1 image is identified in [the recovery report](residual-extraction-recovery.md). Parameter-string references lead to registration at `0x101f65a24`; corresponding named wrappers identify the bass frequency setter (`0x101f6e634`), sample-rate setter (`0x101f6e21c`), and main processing entry (`0x101f6ecd4`). The latter calls the modern sample routine at `0x10452a388`. Native disassembly independently checks its arithmetic; inferred decompiler types and register-pair returns are not trusted as source types.

The frequency setup at `0x104529a6c` establishes a 5 Hz DC section and a separate bass frequency. The modern sample routine's state updates imply a first-order plus Q=1 second-order bass cascade, and a Q=0.5 second-order DC high-pass. These standard transfer functions replace Halftrack's provisional second-order bass/first-order DC defaults. Halftrack implements them independently as normalized direct-form filter sections with double state and the standard tangent function. Its golden impulses use a separate complete transfer polynomial, while steady-state tests use the closed-form Butterworth magnitude law.

This is a structural inference from named registration, call links and arithmetic, not a paired-render claim. The reference uses single-precision operations, fused instructions and a tangent approximation; Halftrack uses a different numerical realization. Parameter scheduling, smoothing duration, width-before-filter transients, filter-switch history and mute behavior remain unmatched or unmeasured. No extracted routine is compiled into Halftrack, no reference code was executed, and legacy device mode is not implemented.

The modern gain/balance callback (`0x104529a34`) calls the normalized stereo gain helper (`0x103e03c40`). Native instructions establish opposing quarter-wave sine gains divided by their center gains. Halftrack therefore replaces its provisional linear balance law with standard constant-power gains normalized to unity at center. Forty-one positions are checked against an independently expressed squared-gain identity. The reference's sine approximation and exact rounding are not reproduced.
