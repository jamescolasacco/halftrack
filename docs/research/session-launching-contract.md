# Session launching contract

This increment implements independently written clip-launching behavior through the pinned engine's native scheduler. It does not use proprietary code or assets.

A track selects one running session clip; rows launch clips together as scenes. Stopping a clip leaves musical transport running. Empty slots act as stop commands, and session ownership can explicitly return to the arrangement. These are public workflow descriptions, not claims of complete feature parity. [Official session workflow](https://www.ableton.com/en/live-manual/12/session-view/).

Global launch quantisation determines when a trigger takes effect on the musical grid. This increment exposes None, one beat, and one bar; clip-specific quantisation, legato, follow actions, launch modes and scene tempo changes remain separate work. [Official launching controls](https://www.ableton.com/en/live-manual/12/launching-clips/).

The engine represents slots as distinct clip owners, scenes as aligned slot rows, and launches as monotonic-beat events. Clips are never moved onto the arrangement to simulate launching. Halftrack computes one boundary per scene, queues mutually exclusive track changes, and lets engine graph processing execute them. [Pinned ClipSlot](https://github.com/Tracktion/tracktion_engine/blob/07e2d674884293f1a6c8f35fb8d1b9f469ffa41f/modules/tracktion_engine/model/tracks/tracktion_ClipSlot.h), [Scene](https://github.com/Tracktion/tracktion_engine/blob/07e2d674884293f1a6c8f35fb8d1b9f469ffa41f/modules/tracktion_engine/model/edit/tracktion_Scene.h), [LaunchHandle](https://github.com/Tracktion/tracktion_engine/blob/07e2d674884293f1a6c8f35fb8d1b9f469ffa41f/modules/tracktion_engine/model/clips/tracktion_LaunchHandle.h), [quantisation](https://github.com/Tracktion/tracktion_engine/blob/07e2d674884293f1a6c8f35fb8d1b9f469ffa41f/modules/tracktion_engine/model/edit/tracktion_LaunchQuantisation.h).

Chosen defaults: eight empty scenes in new projects; bar quantisation; looped slot clips; occupied slots reject import/create until explicitly cleared; empty scene cells stop the track. Structural edits are undoable and media is collected on save. View switching does not stop performance. Transport Stop, relocation, project replacement, and explicit Return to Arrangement must cancel stale queued launches. Current WAV export remains arrangement export; a session performance recorder is not implied.

Verification must inspect audible generated signals around requested beat boundaries, exclusive switching, repeated loop cycles, MIDI synthesis, scene alignment and stopping. Saved/reopened/relocated projects must preserve slot IDs, notes, source ownership and quantisation; missing slot media must reject loading without replacing the current edit. Native-device latency and third-party plug-in timing require separate measurements.

Observed integration corrections: audio slots keep the native beat-based tempo mode; disabling it selected an invalid time-based reader for native launcher content. Generated-signal tests exposed two upstream handoff faults: arrangement audio could return before message-thread ownership publication, and MIDI-only arrangement notes were not stopped at takeover. A separately pinned native patch latches ownership in graph processing and fixes MIDI boundary ordering. The original tests record red/green evidence; no proprietary implementation is used.

Scope limits: scene submission uses sequential native handle calls, so its common boundary is not an atomic cross-thread batch. Serialized synthetic calls are sample-aligned; callback interleaving can split an immediate or late scene. Empty cells take silent ownership of arrangement-only and source-free tracks through the same native boundary scheduler. Ownership remains after Stop, graph rebuilds, source insertion and all-scenes removal until Return; project reopen clears transient ownership. A non-grid transport loop launches at its first contained grid point, falling back to the loop start when none exists. These are bounded implementation choices and gaps, not measured identity with the reference application.

The empty-target regression failed before correction because the arrangement retained its 0.12-level generated signal after the boundary. Commit `b24cb42` passes the focused suite in 3.75 seconds; the integrated four-suite run passes in 69.62 seconds. The test explicitly dispatches deferred graph updates at structural-rebuild checkpoints. It measures generated graph output and does not claim physical device timing or atomic concurrent scene submission.
