## Halftrack implementation and regression

[SubtractiveSynthPlugin::applyToBuffer](../../src/SubtractiveSynth.cpp) consumes complete parameter packets at callback entry, keeps the latest packet, then divides audio around timestamped MIDI events. Timestamp conversion includes the engine MIDI offset and rounds to the nearest sample; a boundary event updates state before the next rendered sample. The DSP maintains phase, envelope, filter and deterministic noise state across render calls. It has no reference-style fixed internal adapter. These are Halftrack implementation facts, not claims about the reference.

Existing [MIDI tests](../../tests/MidiTests.cpp) already cover callback PCM at fixed block sizes 1/31/128/512/2048, nonzero destination/MIDI offsets, rounded boundary events and controller changes. Separate [oscillator fixtures](synth-oscillator-contract.md) check sound against independent filter/waveform outputs. The uncovered seam was the combination of changing host block sizes, sample rate and parameter packets while notes remain active.

`variableBlockCallbackTests` adds 36 actual plug-in scenarios: 44.1/48/96 kHz, four starting waveforms and fixed-128/fixed-512/mixed blocks. The mixed sequence is 1/31/257/2/1024/63/509 samples. Every schedule explicitly splits at samples 733 and 1877, where three valid settings packets are queued; only the last should affect the following audio. Sixteen note, pitch-wheel, sustain and reset-controller events retain their absolute positions. The first pitch-wheel event arrives at sample 127.75 and rounds to the first fixed-128 block end at every sample rate. Each result checks every stereo sample, varying destination/MIDI offsets, untouched surrounding samples, sounding content, complete release and a partial final block.

The oracle advances the existing DSP one sample at a time with the same absolute event/parameter timeline. It therefore checks callback timing, queue coalescing and held-note continuity; it does not independently validate the DSP equations or reference equivalence. Independent sound fixtures remain unchanged. Parameter packets have no timestamps, so this test deliberately makes changes only at shared host boundaries and does not assume unsupported mid-block automation.

Validation: all 27 integrated native acceptance suites passed in 422.51 seconds, including the initial 36 scenarios. After the one-line strengthening that makes end-of-block rounding explicit at every rate, the final build and focused Session acceptance passed in 61.57 seconds. Schedule arithmetic, report links and whitespace checks also pass. No production change or reproduced synthesis defect is claimed by this review. If these scenarios fail, isolate the earliest differing sample and event/packet boundary before changing production code. Reference latency or fixed-size processing should only be added after resolving initialization and obtaining paired measurements; static buffer capacities are not a latency specification.
